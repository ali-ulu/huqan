# Code of Conduct

## Our standard

HUQAN welcomes technical discussion, criticism, bug reports, security research, documentation improvements, and contributions from people with different backgrounds and experience levels.

Participation should remain professional and focused on the work. Examples of expected behavior include:

- disagreeing with ideas without attacking people;
- giving reproducible technical evidence where possible;
- respecting security disclosure boundaries;
- accepting correction when a claim exceeds the available evidence;
- helping keep issues and pull requests scoped and reviewable.

Unacceptable behavior includes harassment, threats, discriminatory or demeaning language, deliberate disruption, publication of private information, and knowingly exposing secrets or unpatched vulnerability details in public channels.

## Technical disagreements

HUQAN is a trust and verification project, so disagreement about claims, threat models, architecture, benchmarks, or safety boundaries is expected. Resolve those disagreements through source, tests, specifications, measurements, and clearly labeled assumptions rather than status or volume.

## Security reports

Sensitive vulnerability details must follow [SECURITY.md](./SECURITY.md), not public Issues or Discussions.

## Enforcement

Repository maintainers may edit, hide, lock, or remove content and restrict participation when behavior materially violates this policy or creates a security risk.

If a moderation concern cannot safely be raised publicly, use an appropriate private GitHub channel available for the repository.

## Scope

This policy applies to repository Issues, Pull Requests, Discussions, Wiki contributions, and other project-managed collaboration spaces.
